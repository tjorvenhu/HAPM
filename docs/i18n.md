# Sprachen der Oberfläche

HAPM spricht Deutsch und Englisch. Deutsch ist die Quelle: jeder Text steht im
Code auf Deutsch und ist zugleich sein eigener Schlüssel. Englisch kommt aus
einem Wörterbuch. Fehlt ein Eintrag, erscheint der deutsche Text, nie ein
Schlüssel, und `tests/i18n/dictionary.test.ts` meldet die Lücke.

## Wo was liegt

| Datei | Wofür |
|---|---|
| `lib/i18n/locale.ts` | `Locale` (`'de' \| 'en'`), Cookie `hapm-lang`, Regel für `Accept-Language` |
| `lib/i18n/translate.ts` | `translate`, `msg`, `msgid`, `plural`, `createTranslator` |
| `lib/i18n/format.ts` | Datum, Zahlen, Zeitspannen, Größen je Sprache |
| `lib/i18n/server.ts` | `getLocale()`, `getT()`, `setLocaleCookie()`: Sprache einer Anfrage |
| `lib/i18n/react.tsx` | `I18nProvider`, `useT()` im Browser |
| `lib/i18n/en/*.ts` | das Wörterbuch, je Bereich eine Datei |
| `scripts/i18n/scan.ts` | liest den Quelltext für Test und Bericht |
| `scripts/i18n-report.ts` | zählt, was noch nicht übersetzbar ist |

`lib/i18n` außer `server.ts` und `react.tsx` ist rein (kein `lib/db`, kein
React, kein `next`). Mails und die statischen Fehlerseiten von HAProxy
benutzen dieselben Funktionen: `createTranslator(locale).t(…)`.

## Welche Sprache gilt

1. die Wahl am Konto (unter „Konto", gespeichert in `user_state.locale`),
2. sonst das Cookie `hapm-lang` (der Umschalter vor der Anmeldung setzt es,
   Anmeldung und Konto spiegeln die Wahl hinein),
3. sonst der Browser: Englisch, wenn Englisch vor Deutsch steht oder keine der
   beiden genannt ist; ohne Kopfzeile Deutsch.

Außerhalb einer Anfrage (Scheduler, Tests) gilt Deutsch. Das Wurzel-Layout
liest für die Sprache nur Cookie und Browser, ohne Datenbank (aus der
Datenbank liest es nur das eigene Aussehen, `docs/betrieb.md`, „Darstellung“); `AppShell` stellt nach dem Laden
der Sitzung auf die Wahl am Konto um.

## Einen Text übersetzbar machen

**Client-Komponente**

```tsx
const { t, plural, rich, locale } = useT();
<h1>{t('Konto')}</h1>
<p>{t('Angemeldet als {name} ({email}).', { name, email })}</p>
```

**Server-Komponente, `generateMetadata`, Route mit eigenem Text**

```ts
const { t } = await getT();
return { title: `${t('Anmeldung')} · HAPM` };
```

**Meldung einer Route.** Geworfen, nicht mit `fail()`: nur `handleError` kennt
die Sprache der Anfrage.

```ts
throw new ApiError(msg('Die Gruppe {name} gibt es schon.', { name }), 409);
```

`err.message` bleibt der deutsche Text samt Werten, für Logs. Ein schlichtes
`new ApiError('…')` ohne `msg` funktioniert weiter und wird ebenfalls
nachgeschlagen, solange es keine Werte einsetzt. Meldungen des Anmeldedienstes
(Better-Auth) übersetzt `lib/auth/errors.ts` über ihren Code.

**Text, der als Zeichenkette weiterwandert** (Beschriftungen in Tabellen,
Rückgabe einer Prüfung, Text aus `lib/`, den erst die Seite zeigt): mit
`msgid('…')` markieren, beim Zeigen `t(wert)`. `msgid` gibt den Text
unverändert zurück, der Test findet ihn so trotzdem.

```ts
const LABELS = { running: msgid('Läuft') };   // lib oder Modulkonstante
<span>{t(LABELS[run.status])}</span>             // Seite
```

**Mehrzahl.** Deutsch und Englisch teilen die Regel (genau 1 ist Einzahl, auch
0 ist Mehrzahl). Jede Form ist ein eigener Schlüssel, `{count}` kommt mit
Tausendertrennung hinein:

```ts
plural(n, { one: '{count} Ziel', other: '{count} Ziele' })
```

**Satz mit Element darin** (`<code>`, `<strong>`, Link):

```tsx
rich('Dort setzt {command} ein neues Passwort.', { command: <code>hapm-admin</code> })
```

**Datum und Zahlen** immer über `lib/i18n/format.ts` mit `locale`:
`formatDate(locale, iso)`, `formatDateTime`, `formatRelative(locale, now, iso)`,
`formatDuration`, `formatNumber`, `formatShare`, `formatBytes`, `formatKb`,
`formatMs`, `formatCountShort`. Kein `toLocaleString('de-DE')` mehr in einer
Seite. `components/system/format.ts` und `ui/charts/palette.ts` reichen dorthin
durch (Sprache als letzter, optionaler Parameter, Vorgabe Deutsch).
`app/(app)/reverse-proxy/statistiken/format.ts` ist noch eine eigene Sammlung:
beim Umstellen der Statistik auf `formatCount`, `formatCountShort`, `formatKb`,
`formatBytes`, `formatMs`, `formatShare` umziehen (Modulkonstanten je Sprache,
der Grund steht im Kopf der Datei).

**Englisch eintragen:** in die Datei des Bereichs unter `lib/i18n/en/`. Ein
Schlüssel steht in genau einer Datei; was mehrere Bereiche brauchen, steht in
`common.ts`. Vor dem Anlegen suchen, ob es den Schlüssel schon gibt.

### Was der Test verlangt

- Jeder Schlüssel aus `t`, `msg`, `msgid`, `rich`, `translate(locale, …)` und
  `plural(…, { one, other })` steht im Wörterbuch, jeder Eintrag wird benutzt.
- Platzhalter sind in Schlüssel und Übersetzung dieselben.
- Kein Schlüssel wird zusammengesetzt: kein `` t(`…${x}…`) `` und kein
  `t('a' + 'b')`. `t(bedingung ? 'a' : 'b')` geht.
- Ein Schlüssel steht in genau einer Datei des Wörterbuchs.

Texte, die noch nicht über `t()` laufen, machen den Test nicht rot. Sie zählt
`pnpm i18n:report` (mit `-- --texts` jeder Text samt Zeile, mit `-- lib/dns`
nur ein Pfad).

## Was nicht übersetzt wird

- **Kennungen auf der Platte und in `haproxy.cfg`** (`hapm_lock_…`, Cookie
  `HAPMSRV`, Pfade, Namen von Backends): Konfigurationen hängen daran.
- **Felder und Werte der API** (`status: 'running'`, Fehlercodes,
  `/api/internal/*`): Programme lesen sie, nicht Menschen. Die API unter
  `/api/internal` antwortet mit Meldungen in der Sprache der Anfrage wie jede
  Route, Skripte sollen sich nach Status und Feldern richten.
- **Logzeilen** (`console.*`) und **Audit-Details**: das sind Aufzeichnungen.
  Sie bleiben, wie sie geschrieben wurden, sonst stünde in einem Protokoll je
  nach Leser etwas anderes. Die Namen der Aktionen (`login`, `2fa_failed`)
  bekommen in der Oberfläche übersetzte Beschriftungen.
- **Gespeicherte Texte mit Werten** (Schritte eines Laufs mit eingesetztem
  Namen): bleiben deutsch, bis ihr Speicherformat `{ text, params }` trägt.
  Gespeicherte Texte ohne Werte, die als `msgid` entstehen, übersetzt die Seite
  mit `t(gespeicherterText)`.
- **Eigennamen und Befehle**: HAPM, HAProxy, acme.sh, Let's Encrypt,
  `docker exec …`.
- **Doku, README und `install.sh`** bleiben deutsch.
- **Mails** haben eine eigene Sprache: `Settings.mailLocale`, einzustellen unter
  „Benachrichtigungen", weil sie an mehrere Empfänger gehen. Eine Mail an genau
  eine Person über ihr eigenes Konto (Passwort zurücksetzen, Passkey) nimmt
  deren Sprache (`accountMailLocale()` in `lib/auth/mail.ts`). Meldungen des
  Mailservers bleiben deutsch: sie werden als „letzter Versand" gespeichert.
- **Fehlerseiten von HAProxy** haben Vorgabetexte auf Deutsch und Englisch,
  gewählt im Design (`PageDesign.locale`, Seite „Fehlerseiten"). Ohne Wahl
  bleiben die Dateien byte-genau wie vor der Übersetzung. Eigene Texte bleiben
  eigene Texte.

## Stil des Englischen

- **Amerikanisches Englisch**: *canceled*, *color*, *license*, Datum als
  `11/24/2026` (`en-US`).
- Kurz und sachlich, wie das Deutsche. Konkretes Substantiv statt Adjektiv.
- Satzzeichen wie im Schlüssel: endet der deutsche Text mit Punkt, Doppelpunkt
  oder Auslassung, tut es der englische auch. Keine Gedankenstriche als
  Satzzeichen (der Test prüft „ – " und „ — "), keine Emoji.
- Aus „Sie" wird ein schlichtes *you* oder der Imperativ: „Bitte geben Sie den
  Code ein." → *Please enter the code.*
- Groß nur am Satzanfang und bei Eigennamen (*Error pages*, nicht *Error Pages*).
- Anmelden/Abmelden: *sign in* / *sign out*, das Substantiv *sign-in*.
